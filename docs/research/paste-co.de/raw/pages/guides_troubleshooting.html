Troubleshooting

MSB8020 Error

Make sure WDK is installed fully and correctly.

Can't find pattern

If KDMapper fails and the log contains Can't find pattern the one of following reasons may occurred:

  • Your KDMapper version is outdated. Ensure you build the newest KDMapper from https://github.com/TheCruZ/kdmapper and try again.
  • Your Windows version is outdated. Try to update your Windows to the newest version. Afterwards try again.
  • KDMapper does not support your Windows version.

You may use another mapping method as described in the Mapper guides.

Nal is already in use

[-] \Device\Nal is already in use.

Use: https://github.com/VollRagm/NalFix

Additional Troubleshooting Steps

If none of the errors above happened, the following general things may help:

  • Check that your path does not contain any spaces/invalid characters (aka. non-ascii characters).
  • Check for interfering Windows security features ("How to disable windows security features for driver loading").
  • Check for applications which may block KDMapper: Vanguard and other anticheats (Faceit, etc.) will instantly load the second your PC boots. Meaning KDMapper will be blocked from loading your driver.

MSB4062

FOR PEOPLE WHO CAN'T READ: DOWNGRADE TO VS2022

The "ValidateNTTargetVersion" task could not be loaded (MSB4062)

If Visual Studio throws an error stating The "ValidateNTTargetVersion" task could not be loaded from the assembly... and references Microsoft.DriverKit.Build.Tasks.18.0.dll, it means your WDK (Windows Driver Kit) installation is corrupted, missing dependencies, or mismatched with your Windows SDK version.

1. Ensure SDK and WDK Versions Match Exactly

The WDK requires the exact matching version of the Windows SDK to compile drivers.

  1. Open the Visual Studio Installer.
  2. Click Modify on Visual Studio 2022.
  3. On the right side under "Installation details", expand Desktop development with C++.
  4. Scroll down and make sure your Windows 11 SDK version matches the version in the error path (e.g., 10.0.26100.0). If it isn't, check it and install it.

2. Verify the WDK Visual Studio Extension is Enabled

Sometimes the WDK installs on your computer, but the plugin for Visual Studio fails to enable.

  1. Open Visual Studio.
  2. Go to Extensions -> Manage Extensions at the top.
  3. Click on Installed on the left.
  4. Look for Windows Driver Kit.
  5. If it is disabled, enable it. (If it is not there at all, your WDK did not install correctly into Visual Studio).

3. Repair the WDK Installation

If the SDK matches and the extension is there, the actual .dll file the compiler is looking for is legitimately missing or corrupted on your hard drive.

  1. Go to Add or Remove Programs (or Installed Apps) in Windows settings.
  2. Search for Windows Driver Kit.
  3. Click the three dots (or right-click) and select Modify or Repair.
  4. Let the installer run purely as a Repair operation. It will redownload and replace the missing dll.

4. Ensure Spectre Mitigations are Installed (Bonus fix)

WDK projects require Spectre-mitigated libraries enabled by default. While you are in the Visual Studio Installer (from Step 1), make sure you also checked:

  • MSVC v143 - VS 2022 C++ x64/x86 Spectre-mitigated libs (Latest)

After checking these, restart Visual Studio, make sure you have Release | x64 selected at the top, and try hitting Ctrl+Shift+B again.
